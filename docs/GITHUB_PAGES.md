## Local checks

Use Node 22.12+ (22.23.3 is used by CI) and Git. From the project root:

```powershell
cd frontend
npm ci
npm run build
npm run test:pages
# Optional browser smoke check, with installed Microsoft Edge:
npm run test:pages -- --browser=msedge
npm run preview
# Open the local preview under /mediastris-website/.
cd ..
node scripts/check-secrets.mjs
```

`npm run dev` continues to use `/` and proxy `/api` to Spring Boot on port 8080.
Production builds default to `/mediastris-website/`. Set `VITE_BASE_PATH=/` in
`frontend/.env.local` or the build environment for root-domain hosting. Do not
set that override for this GitHub Pages repository.

BrowserRouter uses Vite's base as its basename. All known route documents,
including service, About, Careers, article and legacy URLs, are generated by
`metadata.mjs`. GitHub Pages serves their directory indexes on direct visits
and refreshes. `404.html` boots the same app on unmatched paths, preserving the
original URL, query and fragment. Such responses retain the host's HTTP 404
status; the app displays its existing not-found view. No hash-router URL migration
or external rewrite service is needed.

## Enable Pages and verify deployment

In the repository's **Settings → Pages → Build and deployment**, choose
**GitHub Actions** as Source. The workflow runs on pushes to `main`; if the first
run happened before Pages was enabled, rerun it from Actions, or:

```powershell
gh workflow run deploy.yml --repo ronit4824/mediastris-website
gh run list --repo ronit4824/mediastris-website --workflow deploy.yml --limit 1
# Use the actual run ID returned above:
gh run watch RUN_ID --repo ronit4824/mediastris-website --exit-status
gh api repos/ronit4824/mediastris-website/pages --jq .html_url
```

The deployment job reports its actual `page_url`. Use that returned URL, not a
guessed URL, for verification. After a successful deployment, fetch the root,
`about-us/vision/`, a service detail page, `insights/`, `careers/openings/` and
`contact/` beneath that URL. Verify HTTP status, asset loading, menu navigation
and refreshes in a browser. Inspect the contact preview notice. Do not report
publication success until those checks pass. This preparation does not include
a verified public GitHub Pages URL.

## Backend-dependent functionality

The workflow builds/uploads only `frontend/dist`. It does not build, start or
deploy Java. All Spring Boot sources and tests remain in `backend/`.

| Feature | Pages-only behavior | Requirements to enable |
| --- | --- | --- |
| Enquiry form (`POST /api/contact`) | Visible, submission disabled, clear preview notice | Hosted Java API, SMTP host/account, approved sender and receiver |
| Careers applications and resume upload (`POST /api/careers/apply`) | Closed without approved roles; real submission disabled without API | Hosted Java API, approved jobs, SMTP and `CAREERS_RECEIVER_EMAIL` |
| Google reviews (`GET /api/reviews`) | Demo reviews hidden; GOOGLE mode reports unavailable without API | Hosted Java API, Google Place ID and server-only Google API key |
| Optional internal SMS | Unavailable | Backend, approved SMS provider account/configuration; disabled by default |
| Pages, images, menus, themes, maps links and approved public contact links | Static frontend functionality available | Public contact links require approved public values |

For a separately deployed backend, set repository **Actions variable**
`VITE_API_BASE_URL` to its public HTTPS **origin only** (no path or credentials),
then rebuild. Requests use `<origin>/api/...`. Configure backend `CORS_ORIGINS`
for the frontend's origin (scheme and hostname, **no repository path**), expose
the API through HTTPS, and configure its binding/proxy as appropriate for the
hosting provider. Keep rate limits/upload limits and provider credentials on
the server. No server or SMTP credentials belong in GitHub Pages assets.

Optional public Actions variables: `VITE_CONTACT_PHONE`, `VITE_CONTACT_EMAIL`,
`VITE_WHATSAPP_NUMBER`, `VITE_REVIEWS_MODE`. Vite variables are public build-time
values. The workflow forces `VITE_SHOW_DEMO_REVIEWS=false`. Sample jobs and
unapproved project scenarios remain development-only. Existing draft labels,
illustrative-image disclosures and `noindex` restrictions remain intact; client
review is still required before treating content as approved company claims.
